Aim and scope

Implement 2:1, 4:1 and 8:1 multiplexers in Verilog-2001, then verify every select value against every data pattern for each width.

A multiplexer is a digital selector: several data inputs share one output, and the select lines choose which input is connected. This experiment uses three widths so the relationship between select-line count and input count is visible: one select line selects between 2 inputs, two select lines between 4, and three select lines between 8.

The 2:1 multiplexer is written as a conditional assignment. The 4:1 and 8:1 multiplexers use an always @* block with a case statement, so every select value has an explicit branch. The testbench checks all 8 combinations of the 2:1 device, all 64 data/select combinations of the 4:1 device, and all 2,048 data/select combinations of the 8:1 device.

Learning objectives

  • Express a 2:1 multiplexer with the conditional operator.
  • Express wider multiplexers with a case statement inside always @*.
  • Relate n select lines to 2n data inputs.
  • Explain why a multiplexer output is a reg when it is assigned in a procedural block.
  • Verify every select path and every data pattern for all three widths.
  • Recognise the incomplete-assignment latch hazard in combinational always blocks.

Theory and working principle

A multiplexer performs a many-to-one selection. For a device with 2n data inputs, n select lines encode the index of the input that reaches the output. If s = 0, a 2:1 multiplexer passes d0; if s = 1, it passes d1. A 4:1 multiplexer uses two select bits, so s = 2'b10 passes d2. An 8:1 multiplexer uses three select bits, so s = 3'b101 passes d5.

The Boolean form of a 2:1 multiplexer is y = (~s & d0) | (s & d1). Each product term is enabled by one value of the select line. The conditional operator s ? d1 : d0 describes the same function more compactly and is the form used in the design.

For wider multiplexers the sum-of-products grows quickly: a 4:1 device has four three-literal product terms, and an 8:1 device has eight four-literal terms. A case statement maps each select value directly to its data input, which is easier to read and less error-prone than a long expression. The synthesis result is still a multiplexer; the case is a description, not a command to build a priority chain.

A multiplexer is not a decoder. A decoder takes a binary code and asserts one of several outputs; a multiplexer takes several data inputs and routes one of them to a single output. The demultiplexers in Experiment 06 are closer to decoders with data gating.

The indexed form d[s] is valid Verilog-2001 and describes exactly the same selection. The design spells the cases out instead, because an explicit case makes each path visible to a reader who is checking the truth table line by line.

Line-by-line explanation

Design

  • assign y = s ? d1 : d0; is the conditional operator. When s is 1, y takes d1; otherwise it takes d0.
  • always @* re-evaluates the block whenever any signal read inside it changes. This is the combinational sensitivity list.
  • case (s) compares the select value against each listed constant using four-state equality.
  • 2'b00: y = d[0]; and the following items map each select code to one data bit.
  • default: y = 1'b0; guarantees an assignment for any value not covered, including x and z. It also prevents a latch.
  • output reg y is required because y is assigned procedurally. The reg keyword does not imply a hardware register here; it only means a procedural variable.

Testbench

  • pattern walks all data values for each select. For mux2, the loop covers 4 patterns × 2 selects = 8 checks.
  • {m2_d1, m2_d0} = pattern[1:0]; packs the two data bits in the order used by the comparison.
  • The 4:1 section first prints a four-row path check with m4_d = 4'b1010, then runs 64 exhaustive checks.
  • The 8:1 section does the same with m8_d = 8'b10101010 and then 2,048 checks.
  • if (m4_y !== m4_d[s]) compares the output with the indexed data bit; s is an integer used as the index.
  • checks counts every comparison, and the final line reports the total.

Common mistakes and troubleshooting

Swapping the select bits

Writing case ({s[0], s[1]}) reverses the index. The output then follows a different data line for the same numeric select value.

Declaring a procedural output as wire

An output assigned inside always must be a reg in Verilog-2001. A wire would produce a compile error.

Omitting the default

Without a default, an uncovered select value leaves y unassigned and can infer a latch. The design assigns 0 in the default branch.

Using always @(s)

Listing only the select line misses changes on the data inputs. Use always @* so every read signal is in the sensitivity set.

Confusing a multiplexer with a decoder

A multiplexer routes one of many inputs to one output. A decoder converts a code into a one-hot output set. Experiment 06's demultiplexers are the routing counterpart.

Assuming d[s] is out of range safe

An index outside the declared range yields an unknown bit. The explicit case avoids that by covering every legal select value and defining a default.

Revision points

  • An n-bit select chooses among 2n data inputs.
  • 2:1: y = s ? d1 : d0; wider devices can use case or d[s].
  • Procedural assignments require reg outputs; continuous assignments require wires.
  • always @* plus a complete case describes combinational logic without a latch.
  • The testbench checks 8 + 68 + 2,056 = 2,132 combinations.
  • A multiplexer selects one input; a demultiplexer routes one input to one of several outputs.
