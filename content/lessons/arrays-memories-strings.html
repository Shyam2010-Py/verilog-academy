A vector is not an array

A vector is one word: several bits that belong together and are operated on as a unit. An array is a collection of words: each element has the same width, and the array is addressed by an index. In Verilog-2001 the array form you will use most is the memory, which is an array of vectors.

The distinction sounds academic until you try to assign a whole memory in one statement, pass it through a port, or read it as if it were a single wide bus. Then the language is strict in ways that vectors are not.

Declaring and addressing a memory

Vector versus memory
reg [7:0] word;          // one 8-bit vector
reg [7:0] mem [0:3];     // four 8-bit words: depth 4, width 8
reg [7:0] mem2 [0:255];  // 256 words of 8 bits
  • The first range, [7:0], is the width of each word.
  • The second range, [0:3], is the depth: the number of words. Address 0 is valid, address 4 is not.
  • mem[2] selects one word (eight bits). mem[2][3] selects one bit of that word. mem[2][7:4] selects a part of that word.
  • Verilog-2001 provides one unpacked dimension per array. Multi-dimensional arrays such as reg [7:0] mem [0:3][0:3] are a SystemVerilog feature, not Verilog-2001.

A whole memory cannot be assigned in one statement, compared as one value, or passed through a port in Verilog-2001. You read and write it one word at a time, usually inside a loop or with a system task. If a design needs to move a whole memory across a module boundary, the usual solutions are to expose an address/data interface or to flatten the array into one wide vector deliberately.

Line by line

  • reg [7:0] mem [0:3]; declares four words of eight bits. The total storage is 32 bits, but there is no single 32-bit signal named mem.
  • reg [8*5-1:0] label; is a 40-bit vector, exactly enough for five characters. 8*5-1 evaluates to 39, so the range is [39:0].
  • label = "HELLO"; packs the characters into the vector. The first character occupies the most significant byte, so %0s prints HELLO in the expected order.
  • for (i = 0; i < 4; i = i + 1) visits each address. mem[i] = 8'h10 + i[7:0]; writes 0x10, 0x11, 0x12, 0x13. The i[7:0] slice keeps the expression eight bits wide; i itself is a 32-bit integer.
  • mem[2] is 0x12, or 00010010. mem[2][3] is bit 3, which is 0. mem[2][7:4] is the high nibble, 0001.
  • %h prints each byte in hexadecimal, which is easier to scan than eight binary digits.

The memory contents increase by one per address, the bit and part selects match the binary value of 0x12, and the string prints intact. Nothing here proves that synthesis will build a RAM: a four-word memory with asynchronous reads is likely to become registers, while a larger memory with a synchronous read port may become a RAM macro. That mapping is a synthesis decision, not a language rule.

Initialising memories

Testbenches and FPGA prototypes often need a memory preloaded with data. Verilog provides two simulation system tasks for this:

Simulation-only memory loading
$readmemh("init.hex", mem);   // hexadecimal words
$readmemb("init.bin", mem);   // binary words

These tasks read a text file at simulation time. They are not synthesizable, and the file path is resolved by the simulator, so a design that depends on them cannot be handed to synthesis unchanged. FPGA flows usually provide a vendor-specific way to initialise block RAM from a file; ASIC flows load memory through a test interface or a ROM mask.

Common mistakes

  • Assigning the whole memory. mem = 0; is illegal. Write a loop, or use a system task in simulation.
  • Treating mem as one wide vector. mem[31:0] is not the concatenation of four words; that syntax is a bit-select on a non-vector and is rejected.
  • Confusing width and depth. In reg [7:0] mem [0:3], 8 is the width and 4 is the number of words. Reversing them silently changes the hardware.
  • Addressing out of range. mem[4] in a [0:3] memory reads x; writing it is ignored or produces x depending on the simulator. No error is guaranteed.
  • Passing a memory through a port. Verilog-2001 does not allow it. Expose an address and data interface, or flatten the storage.
  • Assuming a string is a string type. It is a packed vector of bytes. Operations are vector operations, and the leftmost character is the most significant byte.

Revision points

  • A vector is one word; a memory is an array of words with a width and a depth.
  • reg [7:0] mem [0:3] means four words, eight bits each; address 0 to 3.
  • Verilog-2001 allows one unpacked array dimension and does not allow whole-memory assignment or memory ports.
  • Strings are packed vectors of bytes; %s prints them, leftmost character first.
  • $readmemh and $readmemb initialise memories in simulation only.
