Two assignment operators, two meanings

= is the blocking assignment. <= is the non-blocking assignment. Both put a value into a variable, but they schedule that update differently, and the difference is the single most consequential rule in behavioural Verilog.

Inside an always @(posedge clk) block, the choice decides whether you have described a shift register or a single register copied to itself. The two versions compile without warnings, simulate differently, and synthesise to different hardware. There is no way to tell them apart by looking at the port list.

What the simulator actually does

A simulation time step is divided into regions. The two that matter here are the active region, where procedural statements execute, and the non-blocking update region, where updates scheduled by <= are applied.

  1. Blocking assignmentThe right-hand side is evaluated and the left-hand side is updated immediately. The next statement in the block sees the new value.
  2. Non-blocking assignmentThe right-hand side is evaluated immediately, but the update is queued. Every other statement in the block continues with the old value. The queued updates are applied at the end of the current time step.

That is the whole model. "Blocking" means it blocks the following statements until the value is stored. "Non-blocking" means it does not: the statement schedules an update and moves on.

For combinational logic the difference is usually invisible, because there is only one assignment per signal and no shared state. For sequential logic it is decisive: hardware registers all sample their inputs at the same clock edge, so every right-hand side must be read before any left-hand side is updated. Non-blocking assignment is exactly that behaviour.

A three-stage shift register, both ways

The design contains two modules with identical ports. One shifts with blocking assignments, the other with non-blocking assignments.

{{CODE:examples/verilog/blocking-nonblocking/design.v}}

Line by line: the blocking version

  • q0 = d; updates q0 immediately. The next statement sees the new q0.
  • q1 = q0; therefore copies the value that d just wrote into q0, not the old q0.
  • q2 = q1; copies that same value again.
  • The result is that all three outputs receive d simultaneously. The hardware is one register whose output fans out to three ports, not three registers in series.

Line by line: the non-blocking version

  • q0 <= d; queues q0 = d for the end of the time step.
  • q1 <= q0; reads the old q0, because the queued update has not been applied yet, and queues q1 = old q0.
  • q2 <= q1; reads the old q1 and queues it.
  • At the end of the edge all three updates land together. Each stage receives the value its predecessor held before the edge, which is exactly a three-stage shift register.

The order of the three statements does not matter in the non-blocking version. Reversing them produces identical hardware, because every right-hand side is sampled before any update. That is precisely why non-blocking assignment is required for registers: it makes the description independent of statement order, matching the parallel nature of clocked hardware.

Read the two output columns against the d column.

Blocking column: q2q1q0 is 111 when d is 1 and 000 when d is 0. All three bits change together, one cycle after d. The three names are three views of one storage element.

Non-blocking column: the bit pattern moves one position per cycle. Cycle 0 shows x01; cycle 1 shows 011; cycle 2 shows 110. The 1 enters at q0, reaches q1 on the next edge, and q2 on the edge after that.

The first row deserves a note because it contains an x. At time 5 ns the clock produces a rising edge before the loop has driven any data, with d still 0. That edge loads q0 <= 0 and shifts the uninitialised values right. By the time the loop takes its first sample at 15 ns, q0 is 1, q1 holds the earlier 0, and q2 still holds the initial x. The x is not a bug in the design; it is an uninitialised register being shifted through. Real hardware needs a reset for exactly this reason.

Rules that survive review

Which operator belongs where
ContextUseWhy
always @(posedge clk)<=All registers sample together at the edge.
always @* combinational=Statements model logic that settles immediately; a blocking update lets later statements see the result.
Testbench stimulus=You want the stimulus applied before the next statement, and there is no hardware to model.
Testbench sampling a design<= or a delaySampling right at the edge races with the design's own updates.
Mixing both in one clocked blockAvoidRelies on intra-block ordering and is a reliable source of simulation/synthesis mismatch.

A practical rule taught in most design guides: non-blocking for sequential, blocking for combinational, and never both in the same block. It is not a superstition. It follows directly from the event model.

Common mistakes

  • Using blocking assignments in a clocked block. The shift register collapses into one register, or an accumulator updates mid-block. Both simulate plausibly and are wrong.
  • Mixing = and <= for the same variable. The result depends on statement order in a way that is hard to reason about and that synthesis may not reproduce.
  • Sampling a design output with a blocking read at the clock edge. The testbench races the design. Sample after a small delay, or on the opposite edge.
  • Assuming non-blocking means "slower". It does not. It means "update at the end of the time step". The hardware is the same speed.
  • Using non-blocking assignment for combinational logic. It can create simulation-only pipelines and mismatches at the clock edge; use blocking there.
  • Forgetting that <= in Verilog is not the same as VHDL's signal assignment. The punctuation is similar; the scheduling model is not interchangeable across languages.

Revision points

  • = updates immediately; <= evaluates now and updates at the end of the time step.
  • Clocked blocks use <=; combinational blocks use =; do not mix them in one block.
  • Blocking assignments in a shift register make all stages load the same value; non-blocking assignments make a real pipeline.
  • Non-blocking assignment makes register descriptions independent of statement order.
  • An uninitialised register shifts x through the pipeline until a reset or enough cycles clear it.
