Nets and variables are different things

Verilog has two families of signal objects. A net is a connection: it does not hold a value, it carries whatever its driver puts on it. A variable holds a value between procedural assignments. Confusing the two is the source of a large fraction of beginner compile errors — and of the false belief that reg always means a flip-flop.

The distinction is about how a signal is driven. It is not about whether the final hardware stores a bit.

The two families

Nets and variables in Verilog-2001
FamilyExamplesDriven byTypical role
Netwire, tri, wand, wor, supply0, supply1Continuous assignment, primitive output, module outputWires between hardware
Variablereg, integer, real, time, realtimeProcedural assignment inside initial or alwaysValues updated by procedural code

wire is the default net type. reg is the general-purpose variable type: it is the only type that can be assigned in an always block and then connected to a module output in Verilog-2001. integer is a 32-bit signed variable used for loop counters and arithmetic in testbenches; time is a 64-bit unsigned variable for simulation time; real is a double-precision floating-point value and is not synthesizable.

Four values, not two

Every bit in a Verilog simulation can be 0, 1, x or z:

  • 0 and 1 are the logic levels.
  • x means unknown: an uninitialised variable, a conflict between drivers, or an undriven input.
  • z means high impedance: no active driver. It appears on tri-state buses and on unconnected nets.

These states are a simulation model, not a synthesis promise. A synthesis tool must decide what x means in the hardware it builds; usually it treats it as a don't-care, which can produce a circuit that behaves differently from the simulation. That is why an x in a waveform is a warning, not a value to design around.

Vectors, bit-selects and part-selects

A vector is a named group of bits with a declared range: reg [3:0] nibble; or wire [7:0] bus;. The left number is the most significant bit by convention, but the language only requires a consistent range. [0:7] is legal and reverses the significance; mixing ascending and descending ranges in one design is a reliable way to create confusion.

  • bus[0] selects one bit.
  • bus[7:4] selects a fixed part. The result is four bits wide.
  • bus[base +: 4] is a Verilog-2001 indexed part-select: four bits starting at base and counting upward. It is useful when the slice position is a signal.

Assignment adjusts width automatically. A narrower right-hand side is zero-extended (or sign-extended if signed); a wider right-hand side is truncated to the destination width, keeping the least significant bits. Both are legal, and both are common sources of silent bugs.

Line by line

  • wire [7:0] bus; is a net. It is driven by the continuous assignment assign bus = 8'hA5;.
  • reg [3:0] nibble; and reg [7:0] byte_reg; are variables assigned inside initial. They are not automatically flip-flops; here they are simply procedural storage that holds a value for the print.
  • integer count; is a 32-bit signed variable. -3 fits comfortably.
  • real voltage; holds 1.8; %0.2f prints two decimal places. Reals are simulation-only.
  • time stamp; is 64 bits wide and unsigned. stamp = $time captures the current simulation time.
  • #5; advances to 5 ns. With `timescale 1ns / 1ps, $time returns 5 in nanosecond units, but %t prints in the simulation precision, so the output shows 5000 (1 ps units).
  • bus[7:4] selects the high nibble of 10100101, which is 1010. bus[0] selects the low bit, which is 1.

The reg myth

Despite the name, reg does not mean "register". A reg assigned inside a combinational always @* block describes combinational logic, and synthesis will build gates, not flip-flops. A reg assigned on a clock edge describes a register. The type only says that the value is assigned procedurally.

The practical rule is mechanical:

  • Driven by assign, a primitive, or an instance output → declare a wire.
  • Driven inside always or initial → declare a reg (or another variable type).
  • Module output driven procedurally → output reg in the ANSI port list.

Common mistakes

  • Assigning a wire inside always. Procedural assignment requires a variable. The compiler rejects it.
  • Using assign on a reg. Continuous assignment drives nets. Again, the compiler rejects it.
  • Reading a reg before it has been assigned. It is x at time zero unless initialised. In hardware there is no "uninitialised"; there is a reset strategy.
  • Assuming reg means a flip-flop. Combinational always blocks produce combinational hardware from reg variables all the time.
  • Ignoring width conversion. A 9-bit expression assigned to an 8-bit vector loses the top bit without an error.
  • Multiple drivers on one net. Two continuous assignments to the same wire resolve to x when they disagree. That is contention, not a wired-OR unless you deliberately use wand/wor.

Revision points

  • Nets carry, variables hold. wire is driven continuously; reg is assigned procedurally.
  • reg is not a hardware register; the always block around it decides the hardware.
  • Verilog simulates four states: 0, 1, x, z.
  • Vectors support bit-select and part-select; assignment truncates or extends silently.
  • integer is 32-bit signed, time is 64-bit unsigned, real is simulation-only.
