The smallest pieces of a Verilog file

Before modules, ports or assignments can make sense, a Verilog compiler has to split the file into tokens: identifiers, keywords, numbers, strings, operators and punctuation. Most "mysterious" syntax errors are lexical errors — a number whose width was misunderstood, an identifier that starts with an illegal character, or a comment that swallowed half a file.

This lesson covers the lexical layer only. Semantics such as blocking versus non-blocking assignment come later; here the question is simply what each piece of text means.

Identifiers, keywords and comments

  • Identifiers start with a letter or an underscore, then may contain letters, digits, underscores and $. They are case-sensitive: value and VALUE are two different signals.
  • System task and function names start with $, for example $display and $time. The $ is not part of an ordinary identifier's first character.
  • Keywords are lowercase and reserved. module, always and wire cannot be used as signal names. Verilog is case-sensitive, so Module is an ordinary identifier — but using it is a bad idea.
  • Escaped identifiers begin with a backslash and end at whitespace: \bus[0] is a single identifier. They are rarely needed and easy to misread; prefer legal names.
  • Comments are // to end of line or /* block */. Block comments do not nest, so a /* inside a block comment does not open a second one. A stray */ can silently comment out code.

Number literals

The general form is <size>'<base><digits>, with an optional s before the base for a signed value:

Literal forms used in the example
LiteralMeaningStored value
8'b1010_10108-bit binary; underscores are ignored10101010 (0xAA)
8'hA58-bit hexadecimal10100101 (165)
8'd1658-bit decimal10100101 (0xA5)

Rules that follow from the grammar:

  • If the size is omitted, the literal is 32 bits wide. An unsized decimal such as 5 is a signed 32-bit integer; in a wider context it is extended, and in a narrower context it is truncated.
  • Bases are b (binary), o (octal), d (decimal) and h (hexadecimal), in either case. x and z digits are allowed in binary, octal and hexadecimal, not in decimal.
  • A minus sign is a unary operator applied to the literal, not part of the literal itself. This matters for signedness and width.
  • {n{...}} replicates a concatenation n times; {a, b} concatenates without replication.

Line by line

  • reg [7:0] byte_a; declares an eight-bit variable. The range [7:0] means bit 7 is the most significant bit.
  • 8'b1010_1010 groups the bits for readability; the underscores do not affect the value.
  • %b prints binary and %h prints hexadecimal. The same eight bits appear as 10101010 and aa.
  • 8'hA5 is 165 in decimal, so %0d prints 165. %0d suppresses leading spaces; %d would pad the field.
  • 4'd18 does not fit in four bits. The low four bits of 18 (10010) are 0010, so the value is 2. The simulator warns about the truncation; the warning is useful, not noise.
  • 8'shFB is a signed 8-bit value. 0xFB is 251 unsigned, which is -5 in two's complement.
  • -5 is an unsized signed decimal. It is printed as -5 because the expression keeps its 32-bit signed interpretation.
  • {4{2'b10}} repeats 10 four times, producing 10101010. The inner braces are required.
  • {4'b1100, 4'b1010} joins two four-bit values into eight bits, most significant part first.
  • legal_name_1, value and VALUE are all legal identifiers. The last two are distinct variables, so assigning 4'hA to value does not change VALUE.

Strings and directives

A string is a double-quoted sequence of bytes, one byte per character. "HELLO" is five bytes; assigning it to a wider vector pads on the left with zeros, and assigning it to a narrower vector truncates. There is no separate string type in Verilog-2001; a string is just a packed vector with a convenient literal syntax.

Compiler directives begin with a backtick, not a dollar sign: `define, `include, `timescale, `default_nettype. They are processed before elaboration and are not system tasks. A macro is textual substitution, so parentheses matter: `define WIDTH 4 followed by `WIDTH-1 expands to 4-1, which is fine here, but expressions with operators need care.

Common mistakes

  • Forgetting the size. 5 is a 32-bit signed value, not a 4-bit one. Use 4'd5 when the width is part of the intent.
  • Expecting decimal literals to saturate. They truncate. 4'd18 is 2, and the simulator may only warn.
  • Using a hyphen in an identifier. half-adder parses as half minus adder. Use an underscore.
  • Nesting block comments. A /* inside a block comment does not nest; the first */ closes the comment.
  • Confusing 'd with a decimal point. 4'd2 is a four-bit decimal 2; 4.2 is a real number and is not synthesizable.
  • Treating x and z as ordinary digits. They are simulation states. Synthesis treats them as don't-cares or rejects them, depending on context.

Revision points

  • Identifiers are case-sensitive and may contain letters, digits, underscores and $ after the first character.
  • A sized literal is <size>'<base><digits>; an optional s makes it signed; underscores are ignored.
  • Unsized decimals are 32-bit signed; sized literals truncate silently apart from simulator warnings.
  • Concatenation uses {a, b}; replication uses {n{...}}.
  • Compiler directives start with a backtick; system tasks start with $.
