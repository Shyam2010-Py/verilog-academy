Two languages, one job

Verilog and VHDL are both hardware description languages. Both describe concurrent hardware, both are standardised by the IEEE, and both can be simulated and synthesised. They differ in heritage, type discipline and the way a design is written — not in what hardware can be built.

Verilog grew out of a C-like simulation language and became the dominant language of commercial ASIC and FPGA design. VHDL grew out of Ada and is common in FPGA development, aerospace, defence and mixed-language environments where strong typing is valued. Neither language is inherently faster or smaller; synthesis results depend on the description and the library, not on the spelling.

The table explains why beginners find Verilog quicker to start: a one-bit AND gate is one line, and widths convert implicitly. The same features become hazards at scale. VHDL forces the designer to state types and conversions, which is verbose but catches some classes of error earlier. Professional teams choose according to toolchain, legacy code and verification environment, not according to a universal "better".

Abstraction levels inside Verilog

Verilog is not one language level. The same design can be described at several levels, and the level determines what the simulator and synthesis tool can do with it.

Switch level

Transistors and switches: nmos, pmos, cmos. Used in cell models and analogue-like experiments, not in RTL.

Gate level

Primitive gates and module instances. This is the level of a netlist produced by synthesis.

Dataflow

Continuous assignments: assign y = (a & b) | c;. The equations are combinational hardware.

Behavioural

initial and always blocks with algorithms, conditionals and timing controls.

RTL is the synthesizable subset of behavioural modelling in which every signal is either a register updated on a clock edge or combinational logic between registers. A behavioural block with #10 delays is still behavioural, but it is not RTL. That distinction is the reason a design can simulate beautifully and still fail synthesis.

Line by line

  • `default_nettype none disables implicit nets. The directive is restored at the end of the file.
  • assign y = a & b; is a continuous assignment. The & is bitwise AND; for one-bit operands it is the same as the logic function.
  • The testbench declares reg for the driven inputs and wire for the observed output. That split mirrors the direction of every connection in the design.
  • for (i = 0; i < 4; i = i + 1) walks the four input combinations. {a, b} = i[1:0] drives both inputs in one assignment.
  • #1 separates the stimulus from the observation. The output would settle without it, but the printed table and any waveform become unambiguous.

Choosing a level, not just a language

Most real designs mix levels deliberately:

  • RTL for the blocks you own and need to synthesise. It is readable, portable and verified by simulation.
  • Gate level for library cells, post-synthesis simulation and small glue logic where the exact cell matters.
  • Dataflow for short combinational equations where a truth table or boolean expression is clearer than a procedural block.
  • Behavioural with timing for testbenches, bus functional models and cell models. This code is not the design.

In Verilog the same keywords can appear at several levels, which is why "it compiles" says very little. The question to ask is always: which parts of this file are intended to become hardware?

Common mistakes

  • Assuming the languages are interchangeable. Types, conversion rules and assignment semantics differ. A VHDL design translated token-by-token is usually wrong.
  • Assuming strong typing prevents all bugs. VHDL catches some width and type errors earlier; it does not prove intent or timing.
  • Equating behavioural with non-synthesizable. RTL is behavioural code that synthesis accepts. The presence of always does not make a block unsynthesizable; delays and testbench constructs do.
  • Reading Verilog as C. Statements outside procedural blocks are concurrent descriptions, not sequential instructions.

Revision points

  • Verilog and VHDL are both IEEE-standard HDLs; the choice is driven by toolchain, ecosystem and team, not capability.
  • Verilog's four logic values are 0, 1, x and z; VHDL's std_logic has nine.
  • The four modelling levels are switch, gate, dataflow and behavioural; RTL is the synthesizable behavioural subset.
  • Simulation-only constructs do not belong in RTL, regardless of which HDL is used.
