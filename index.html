module half_adder (
  input  wire a,
  input  wire b,
  output wire sum,
  output wire carry
);

  assign sum   = a ^ b;
  assign carry = a & b;

endmodule
`timescale 1ns / 1ps

module half_adder_tb;
  reg  a, b;
  wire sum, carry;
  integer i;

  half_adder dut (a, b, sum, carry);

  initial begin
    $dumpfile("half_adder.vcd");
    $dumpvars(0, half_adder_tb);

    for (i = 0; i < 4; i = i + 1) begin
      {a, b} = i[1:0];
      #10 $display("a=%b b=%b sum=%b carry=%b",
                     a, b, sum, carry);
    end

    $finish;
  end
endmodule

01 / The approach

Theory, practice and proof.

A hardware engineer does not stop at a description that looks right. The course is built around the same loop a real design team uses: understand the circuit, model it, then verify the behaviour.

Structure before syntax

Start with the design flow, module boundaries and data types. Verilog syntax makes sense once you know what the hardware is doing.

Build the model

Move from gate primitives to dataflow and behavioural descriptions, writing Verilog-2001 that maps to real circuits.

Prove the design

Every idea ends in a testbench and a waveform. If the simulation is wrong, the design is not finished.

03 / Learning path

From first gate to verified design.

A deliberate sequence: learn the language, describe circuits structurally and behaviourally, then validate each idea in the laboratory. No skipped steps and no unexplained code.

01 EC-405 · Unit 1 · 20 periods

Foundations of the language

Understand how hardware is described before writing a line of Verilog.

  • VLSI design flow and the role of HDL
  • Modules, instances, ports and hierarchy
  • Nets, registers, vectors and number systems
02 EC-405 · Unit 2 · 10 periods

Structural and dataflow modelling

Describe a circuit as gates, or as continuous equations over its signals.

  • Gate primitives and delay modelling
  • Continuous assignments and operators
  • Adders, multiplexers, decoders and ALUs
03 EC-405 · Unit 3 · 15 periods

Behavioural modelling

Model processes, timing and state, then prove the behaviour with a testbench.

  • initial, always and timing controls
  • Blocking versus non-blocking assignment
  • Conditionals, loops and user-defined primitives
04 EC-410 · Experiments 1–6

Practical validation

Put the language to work on the bench, from basic gates to arithmetic and routing.

  • Basic logic gates and adders
  • Subtractors and a 4-bit parallel adder
  • Multiplexers and demultiplexers
