EC-410 · Experiment 01

7 gates · 4 input vectors

Laboratory overview EC-405 theory

Aim and scope

Implement the seven basic logic gates — AND, OR, NOT, NAND, NOR, XOR and XNOR — as a single combinational Verilog-2001 module, then prove every output against an independent truth table.

The experiment deliberately keeps all seven gates in one module. Each output is driven by its own continuous assignment, so the design is a direct textual description of the Boolean equations. There is no clock, no state and no test-only logic inside design.v: the same module could be synthesised as seven parallel gates.

Two files form the bench record. design.v contains the gate module. tb.v applies all four input vectors, compares the seven outputs with hard-coded expected values, counts mismatches and prints a table. The transcript you will see later is the actual output of that testbench.

Learning objectives

  • Write a continuous assignment for each of the seven basic gates using Verilog-2001 operators.
  • Distinguish the unary NOT operator ~ from the binary reduction operators that combine two operands.
  • Predict all seven outputs for each of the four combinations of a and b.
  • Explain why the module outputs are declared as wire rather than reg.
  • Compile and run the design in Verilog-2001 mode, then read the transcript as evidence rather than decoration.
  • Recognise the difference between a zero-delay simulation result and a real gate propagation delay.

Theory and working principle

A basic gate is a combinational primitive: its output depends only on the present values of its inputs. The seven gates in this experiment fall into three groups.

  • AND and OR require both inputs. AND is 1 only when every input is 1; OR is 1 when at least one input is 1.
  • NOT is unary. It needs only a, and its output is the complement of that single input.
  • NAND, NOR and XNOR are the complemented forms of AND, OR and XOR. They are written as a negation around the base operation.

XOR is 1 when the inputs differ. XNOR is its complement, so it is 1 when the inputs are equal. In Verilog-2001 the operators are & (AND), | (OR), ~ (NOT), ^ (XOR) and ~^ or ^~ (XNOR). NAND and NOR are written by negating the parenthesised result: ~(a & b) and ~(a | b).

Every output is a wire because a continuous assignment drives it. The simulator evaluates the right-hand side whenever an input changes and schedules the new value on the wire. In this zero-delay model the update is immediate in simulation time; a physical gate would add propagation delay, which is a separate topic.

Read the table by columns, not by memorising gate names. The NAND column is exactly the AND column inverted; NOR is OR inverted; XNOR is XOR inverted. The NOT column depends only on a, which is why it repeats in pairs down the rows.

Boolean equations

ANDy_and = a & b
ORy_or = a | b
NOTy_not = ~a
NANDy_nand = ~(a & b)
NORy_nor = ~(a | b)
XORy_xor = a ^ b
XNORy_xnor = ~(a ^ b)

The parentheses around the NAND, NOR and XNOR expressions are essential. ~a & b means “NOT a, then AND with b”, which is a different function from ~(a & b). The testbench would expose that mistake immediately on the a=0, b=1 row.

Verilog design code

The design is a complete module, not a fragment. `default_nettype none forces every net to be declared explicitly; `default_nettype wire restores the default at the end of the file so that other files compiled afterwards are unaffected.

design.v 
`default_nettype none
`timescale 1ns / 1ps

// EC-410 Experiment 01 - the seven basic gates in one module.
// Every output is a continuous assignment, so each gate is always active.
module basic_gates (
    input  wire a,
    input  wire b,
    output wire y_and,
    output wire y_or,
    output wire y_not,
    output wire y_nand,
    output wire y_nor,
    output wire y_xor,
    output wire y_xnor
);

    assign y_and  = a & b;
    assign y_or   = a | b;
    assign y_not  = ~a;
    assign y_nand = ~(a & b);
    assign y_nor  = ~(a | b);
    assign y_xor  = a ^ b;
    assign y_xnor = ~(a ^ b);

endmodule

`default_nettype wire

Testbench

These are the testbench sources exactly as compiled. The expected values are written as seven-bit constants, independent of the design equations, so the comparison checks the implementation rather than repeating it.

tb.v 
`default_nettype none
`timescale 1ns / 1ps

module basic_gates_tb;
    reg  a;
    reg  b;
    wire y_and, y_or, y_not, y_nand, y_nor, y_xor, y_xnor;

    reg [6:0] expected;
    reg [6:0] actual;
    integer i;
    integer errors;

    basic_gates dut (
        .a(a), .b(b),
        .y_and(y_and), .y_or(y_or), .y_not(y_not),
        .y_nand(y_nand), .y_nor(y_nor),
        .y_xor(y_xor), .y_xnor(y_xnor)
    );

    initial begin
        errors = 0;
        $display("a b | and or not nand nor xor xnor | result");
        $display("----+--------------------------------+-------");

        for (i = 0; i < 4; i = i + 1) begin
            {a, b} = i[1:0];
            #1;
            actual = {y_and, y_or, y_not, y_nand, y_nor, y_xor, y_xnor};

            case ({a, b})
                2'b00: expected = 7'b0011101;
                2'b01: expected = 7'b0111010;
                2'b10: expected = 7'b0101010;
                2'b11: expected = 7'b1100001;
                default: expected = 7'bxxxxxxx;
            endcase

            if (actual !== expected) begin
                errors = errors + 1;
                $display(" %b %b |  %b   %b   %b    %b    %b   %b    %b | FAIL",
                         a, b, y_and, y_or, y_not, y_nand, y_nor, y_xor, y_xnor);
            end else begin
                $display(" %b %b |  %b   %b   %b    %b    %b   %b    %b | pass",
                         a, b, y_and, y_or, y_not, y_nand, y_nor, y_xor, y_xnor);
            end
        end

        $display("checked 4 input combinations, mismatches = %0d", errors);
        $finish;
    end
endmodule

`default_nettype wire

Line-by-line explanation

Design file

  • `default_nettype none makes an undeclared net an error. This is a deliberate safety rule: a misspelled wire should fail compilation, not silently become a one-bit net.
  • module basic_gates (...) declares two scalar inputs and seven scalar outputs. The port order is part of the documentation; the testbench uses named association.
  • output wire is correct because each output is driven by a continuous assignment. A reg cannot be driven by assign.
  • assign y_and = a & b; is a continuous assignment. It is not executed once; it remains active for the whole simulation.
  • ~(a & b) negates the complete AND result. In a vector context ~ is bitwise, but here every value is one bit, so the distinction does not change the result.
  • `default_nettype wire restores the standard default after the module.

Testbench

  • reg a; reg b; are testbench variables because the initial block assigns them procedurally. The design's inputs are wires from the module's point of view, but a procedural driver needs a variable.
  • wire y_and ... receive the design outputs. They are not assigned by the testbench.
  • basic_gates dut (...) instantiates the design with named port connections. Named association avoids a silent port-order mistake.
  • for (i = 0; i < 4; i = i + 1) walks the four input vectors. {a, b} = i[1:0] maps 0 to 00, 1 to 01, 2 to 10 and 3 to 11.
  • #1 advances simulation time by 1 ns and lets the continuous assignments settle before the outputs are read.
  • actual = {y_and, ...} packs the seven outputs into one vector so a single comparison covers the whole row.
  • case ({a, b}) supplies the expected seven-bit pattern for that row. The constants were derived from the truth table, not from the design.
  • !== is a four-state inequality. It treats x and z as mismatches, which is what a verification check should do. The ordinary != could hide an unknown value.
  • errors counts failures. $display prints one row and $finish ends the simulation.

Compilation and simulation commands

Run these from the directory that contains design.v and tb.v. The first command compiles both files into an Icarus simulation image; the second executes it.

Terminal 
iverilog -g2001 -o experiment-01.out design.v tb.v
vvp experiment-01.out

-g2001 selects Verilog-2001. The output file name is arbitrary; experiment-01.out is used here so it is obvious which experiment produced it. A compilation error must be fixed before the simulation is meaningful.

Waveform and timing

This circuit has no clock. A waveform would show a and b changing at the stimulus times and the outputs following after the simulator's zero-delay update. In the testbench each vector is held for 1 ns: vector 00 at 0 ns, 01 at 1 ns, 10 at 2 ns and 11 at 3 ns.

The simulator line $finish called at 4000 (1ps) can look like 4,000 ns. It is not. With `timescale 1ns / 1ps, %0t in Icarus reports the simulation time in the precision unit, so 4000 ps is 4 ns. Four 1 ns vectors therefore end at 4 ns.

Result

All seven gates matched the truth table.

The testbench applied 4 input combinations and reported 0 mismatches. Every row of the captured transcript reads pass, and the seven outputs match the Boolean equations and the diagram.

This is a complete verification of a combinational circuit with two inputs, because four vectors exhaust the input space. There is no untested input value and no clock cycle to miss.

Common mistakes and troubleshooting

Writing ~a & b for NAND

Operator precedence applies NOT to a only. Use ~(a & b). The same warning applies to NOR and XNOR.

Using || or &&

These are logical operators that produce a single true/false result. For gate-level bit operations use | and &.

Assigning a reg continuously

reg cannot be the target of assign. The outputs are wire because they are driven continuously.

Forgetting the settling delay

Reading outputs in the same simulation delta as the input change can show the old value. A small #1 after the stimulus avoids that race.

Comparing with !=

An unknown output can compare as equal under some four-state rules. !== makes x and z explicit failures.

Expecting real gate delay

Continuous assignments have no built-in propagation delay. A zero-delay result proves logic, not timing. Gate delays are modelled separately with # delays.

If compilation fails, read the first error rather than the last. A missing semicolon or an undeclared net caused by `default_nettype none often produces a cascade of later messages.

Viva questions

  1. Why are the outputs declared as wire and not reg?
  2. What is the difference between & and &&? Give a case where they differ.
  3. Which gates are called universal gates, and why?
  4. How would you build an XOR gate using only NAND gates?
  5. What does a simulator value of x mean, and why does the testbench use !==?
  6. Why does the transcript finish at 4 ns rather than 4,000 ns?
  7. Does a zero-delay simulation prove that the physical circuit will meet timing?

Revision points

  • AND is 1 only for 11; OR is 0 only for 00; XOR is 1 when the inputs differ.
  • NAND, NOR and XNOR are the complements of AND, OR and XOR, not different input combinations.
  • Parentheses decide the meaning of a complemented compound expression.
  • Continuous assignments drive wire; procedural blocks drive reg.
  • Four vectors exhaust a two-input combinational truth table.
  • !== is the correct comparison for a self-checking testbench.
