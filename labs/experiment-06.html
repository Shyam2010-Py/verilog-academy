EC-410 · Experiment 06

3 demultiplexers · 28 vectors

Laboratory overview EC-405 theory

Aim and scope

Implement 1:2, 1:4 and 1:8 demultiplexers in Verilog-2001 so that exactly one output follows the data input, then verify every data and select combination.

A demultiplexer is the reverse of a multiplexer: one data input is routed to one of several outputs, chosen by the select lines. All unselected outputs must be driven to 0, not left undriven. That requirement is what makes a demultiplexer more than a decoder — it gates the data, so an unselected output is low even when the selected output is high.

The 1:2 device uses two continuous assignments with the select line and its complement. The 1:4 and 1:8 devices use an always @* block that clears every output first and then sets the selected bit. The testbench checks 4 + 8 + 16 = 28 combinations, which exhausts every device.

Learning objectives

  • Explain the difference between a demultiplexer and a decoder.
  • Implement a 1:2 demultiplexer with data-gated assignments.
  • Use a case statement to route data to one of four or eight outputs.
  • Guarantee that every unselected output is driven to 0.
  • Verify all 28 data/select combinations across the three devices.
  • Recognise how an incompletely assigned output can infer a latch.

The design uses no tri-state buffers. Every output is always driven to a defined 0 or 1, which is simpler to verify and safer for synthesis.

Theory and working principle

A demultiplexer takes one data input and distributes it to one of 2n outputs. The select code names the destination. For a 1:4 device, s = 2'b10 routes din to y[2] and forces y[3], y[1] and y[0] to 0.

The 1:2 case is small enough to write directly. Output y0 is enabled when the select is 0, so y0 = din & ~s. Output y1 is enabled when the select is 1, so y1 = din & s. When din = 0, both outputs are 0 regardless of the select; the data input gates the whole device.

For wider devices the pattern generalises to y[i] = din & (s == i). Only one equality term can be true at a time, so at most one output follows din. The design implements this with a case statement that clears all outputs and then assigns the selected bit.

The contrast with a decoder matters. A 2-to-4 decoder asserts exactly one output for each input code, independent of any data signal. A 1:4 demultiplexer behaves like a decoder whose selected output is ANDed with din. When din = 1 the two look identical; when din = 0 the demultiplexer produces all zeros while the decoder still produces a one-hot pattern.

The equality terms are mutually exclusive, so the outputs can never both be 1 for a nonzero din. That one-hot property is the functional core of a demultiplexer.

Verilog design code

The 1:2 module uses two continuous assignments. The wider modules clear the whole output vector before the case, so every unselected bit is explicitly assigned 0.

design.v 
`default_nettype none
`timescale 1ns / 1ps

// EC-410 Experiment 06 - 1:2, 1:4 and 1:8 demultiplexers.
// Exactly one output receives din; every unselected output is forced to 0.

module demux1_2 (
    input  wire din,
    input  wire s,
    output wire y0,
    output wire y1
);

    assign y0 = din & ~s;
    assign y1 = din &  s;

endmodule


module demux1_4 (
    input  wire       din,
    input  wire [1:0] s,
    output reg  [3:0] y
);

    always @* begin
        y = 4'b0000;
        case (s)
            2'b00: y[0] = din;
            2'b01: y[1] = din;
            2'b10: y[2] = din;
            2'b11: y[3] = din;
            default: y = 4'b0000;
        endcase
    end

endmodule


module demux1_8 (
    input  wire       din,
    input  wire [2:0] s,
    output reg  [7:0] y
);

    always @* begin
        y = 8'b00000000;
        case (s)
            3'b000: y[0] = din;
            3'b001: y[1] = din;
            3'b010: y[2] = din;
            3'b011: y[3] = din;
            3'b100: y[4] = din;
            3'b101: y[5] = din;
            3'b110: y[6] = din;
            3'b111: y[7] = din;
            default: y = 8'b00000000;
        endcase
    end

endmodule

`default_nettype wire

Testbench

The testbench checks each device against a one-hot expected vector. For the wider devices the expected vector is computed by shifting a single 1 into the selected position and masking it with din.

    reg [7:0] expected8;

    demux1_4 u_demux1_4 (.din(d4_din), .s(d4_s), .y(d4_y));
    demux1_8 u_demux1_8 (.din(d8_din), .s(d8_s), .y(d8_y));

Line-by-line explanation

Design

  • assign y0 = din & ~s; drives y0 with the data only when the select is 0.
  • assign y1 = din & s; drives y1 only when the select is 1. When din = 0, both outputs are 0.
  • always @* makes the wider modules combinational. Every signal read inside the block is in the sensitivity set.
  • y = 4'b0000; is the default assignment that clears all outputs before the case.
  • 2'b00: y[0] = din; sets only the selected bit. The other three bits keep the 0 from the clear statement.
  • default: y = 4'b0000; covers unknown select values and reinforces the all-zero behaviour.
  • output reg [3:0] y is a procedural variable because it is assigned inside always. It is still combinational hardware.

Testbench

  • {d2_y1, d2_y0} concatenates the two outputs for a single comparison.
  • expected4 = din ? (4'b0001 << s) : 4'b0000; builds the one-hot pattern and masks it with the data input.
  • The same pattern is used for the 1:8 device with an eight-bit shift.
  • if (d4_y !== expected4) compares the entire output vector, so a wrong unselected output is caught even when the selected output is correct.
  • The active column prints the selected index, or −1 when din = 0, which makes the transcript easier to read.

Result

All three demultiplexers routed the data correctly in every case.

The testbench checked 28 combinations and reported 0 mismatches. In every row exactly one output followed din, and every unselected output was 0, including the all-zero rows where din = 0.

The check compares the complete output vector, not only the active bit, so a stuck-at-one unselected output would have failed the test.

Common mistakes and troubleshooting

Leaving unselected outputs undriven

Assigning only the selected bit without clearing the vector infers storage or produces unknown values. Clear the whole output first, as the design does.

Using OR instead of AND

A selected output must be din & select_term. OR would force the output high even when din is 0.

Reversing the select order

Using {s0, s1} instead of {s1, s0} swaps y1 and y2. The vector comparison catches it only if the testbench checks the full output.

Confusing a demultiplexer with a decoder

A decoder asserts the selected output regardless of data. A demultiplexer gates that output with din, so it produces all zeros when the data input is 0.

Forgetting the default branch

An uncovered select value would leave the outputs at their previous values, inferring a latch. The default restores the all-zero state.

Expecting one-hot when din = 0

The active output is the selected one only if data is present. The transcript's −1 column records the no-data case explicitly.

Revision points

  • A demultiplexer routes one data input to one of 2n outputs.
  • 1:2: y0 = din & ~s, y1 = din & s.
  • Wider devices use y[i] = din & (s == i) or an equivalent case.
  • All unselected outputs are 0, even when din = 1.
  • 28 vectors exhaust the 1:2, 1:4 and 1:8 truth tables.
  • A decoder without data gating is not a demultiplexer.
