Gate Level and Data Flow Modelling

Unit overview

Addition, carry and the missing fifth bit

Adding two four-bit numbers can produce a five-bit result. If the destination is four bits, the top bit has to go somewhere. That "somewhere" is the carry output, and forgetting it is one of the oldest bugs in digital design.

The clean way to model it in Verilog is to perform the addition in a wider context, then split the result: the low bits become the sum, the extra bit becomes the carry. Doing the addition in four bits and trying to recover the carry afterwards is not possible — the information is already gone.

Subtraction is addition in disguise

Two's complement represents -b as ~b + 1. Therefore:

a - b = a + (~b) + 1

One adder, with an inverter on the second operand and a carry-in of 1, can perform both addition and subtraction. In the example, bx = b ^ {4{sub}} inverts every bit of b when sub is 1, and the same sub signal supplies the +1 through the carry input.

In this shared adder, the carry output has a different meaning for subtraction: cout = 1 means no borrow was needed, and cout = 0 means the result went below zero and borrowed. That is a consequence of the a + ~b + 1 formulation, not a separate borrow flag.

Carry is not overflow

The carry out and the overflow flag answer different questions:

  • Carry out is about unsigned range. It says the mathematical result did not fit in four unsigned bits.
  • Overflow is about signed range. It says the signed result crossed from positive to negative or vice versa. Adding two positives cannot produce a negative signed result without overflow; adding two negatives cannot produce a positive one.

For four-bit signed values the range is -8 to +7. 5 + 3 = 8 fits in five unsigned bits but not in four signed bits, so cout = 0 while overflow = 1. The two flags are not redundant; neither can replace the other.

Comparators and the signedness trap

A comparator is a subtraction in disguise: a < b, a == b and a > b are relational operators on the same bits. The trap is interpretation. If the ports are unsigned, 1000 is 8. If the ports are signed, the same bits are -8. The comparison hardware differs because the sign bit must be handled differently.

In Verilog the declaration decides. input wire [3:0] a is unsigned; input wire signed [3:0] a is signed. Mixing a signed signal with an unsigned one makes the comparison unsigned, which is exactly the kind of silent conversion this unit keeps warning about.

One add/subtract unit and two comparators

The example contains an adder/subtractor with carry, zero and overflow flags, an unsigned comparator, and a signed comparator with identical logic but signed ports.

example.v 
`default_nettype none
// Addition and subtraction share one adder; sub inverts B and adds 1.
module addsub4 (
    input  wire [3:0] a,
    input  wire [3:0] b,
    input  wire       sub,
    output wire [3:0] sum,
    output wire       cout,
    output wire       zero,
    output wire       overflow
);
    wire [3:0] bx = b ^ {4{sub}};
    wire [4:0] wide = {1'b0, a} + {1'b0, bx} + sub;

    assign sum      = wide[3:0];
    assign cout     = wide[4];
    assign zero     = (sum == 4'b0000);
    assign overflow = (a[3] & bx[3] & ~sum[3]) |
                      (~a[3] & ~bx[3] & sum[3]);
endmodule

module comparator4 (
    input  wire [3:0] a,
    input  wire [3:0] b,
    output wire       lt,
    output wire       eq,
    output wire       gt
);
    assign lt = (a < b);
    assign eq = (a == b);
    assign gt = (a > b);
endmodule

// The same comparison with signed ports: the bits are identical to
// comparator4, but the interpretation of bit 3 is different.
module comparator4_signed (
    input  wire signed [3:0] a,
    input  wire signed [3:0] b,
    output wire              lt,
    output wire              eq,
    output wire              gt
);
    assign lt = (a < b);
    assign eq = (a == b);
    assign gt = (a > b);
endmodule
`default_nettype wire

Line by line

  • wire [3:0] bx = b ^ {4{sub}}; replicates sub four times and XORs it with b. With sub = 0, bx = b; with sub = 1, bx = ~b.
  • wire [4:0] wide = {1'b0, a} + {1'b0, bx} + sub; zero-extends both operands to five bits before adding, so the carry is captured in wide[4]. The one-bit sub is zero-extended and acts as the carry-in.
  • assign sum = wide[3:0]; and assign cout = wide[4]; split the five-bit result into the four-bit sum and the carry.
  • assign zero = (sum == 4'b0000); is a combinational equality. It is true when the result is zero, which for subtraction also means a == b.
  • assign overflow = (a[3] & bx[3] & ~sum[3]) | (~a[3] & ~bx[3] & sum[3]); detects same-sign operands producing an opposite-sign result. bx is the effective second operand, so the formula works for both addition and subtraction.
  • comparator4 uses unsigned ports, so 1000 is 8. comparator4_signed declares the same bits signed, so 1000 is -8. The expressions are identical; the declarations change the hardware.
tb.v 
`default_nettype none
`timescale 1ns / 1ps

module addsub4_tb;
    reg  [3:0] a;
    reg  [3:0] b;
    reg        sub;
    wire [3:0] sum;
    wire       cout;
    wire       zero;
    wire       overflow;
    wire       lt;
    wire       eq;
    wire       gt;
    wire       slt;
    wire       seq;
    wire       sgt;

    addsub4 dut (
        .a(a), .b(b), .sub(sub),
        .sum(sum), .cout(cout), .zero(zero), .overflow(overflow)
    );

    comparator4 cmp (.a(a), .b(b), .lt(lt), .eq(eq), .gt(gt));
    comparator4_signed scmp (.a(a), .b(b), .lt(slt), .eq(seq), .gt(sgt));

    initial begin
        $display("operation        | sum  cout zero ovf | lt eq gt");
        $display("-----------------+-------------------+---------");

        a = 4'd5; b = 4'd3; sub = 0; #1;
        $display("5 + 3            | %b   %b    %b    %b  |  %b  %b  %b", sum, cout, zero, overflow, lt, eq, gt);

        a = 4'd7; b = 4'd1; sub = 0; #1;
        $display("7 + 1 (overflow) | %b   %b    %b    %b  |  %b  %b  %b", sum, cout, zero, overflow, lt, eq, gt);

        a = 4'd4; b = 4'd2; sub = 1; #1;
        $display("4 - 2            | %b   %b    %b    %b  |  %b  %b  %b", sum, cout, zero, overflow, lt, eq, gt);

        a = 4'd0; b = 4'd1; sub = 1; #1;
        $display("0 - 1            | %b   %b    %b    %b  |  %b  %b  %b", sum, cout, zero, overflow, lt, eq, gt);

        a = 4'b1000; b = 4'd1; sub = 1; #1;
        $display("-8 - 1 (overflow)| %b   %b    %b    %b  |  %b  %b  %b", sum, cout, zero, overflow, lt, eq, gt);

        a = 4'b1000; b = 4'd1; sub = 0; #1;
        $display("signed compare a=%b (-8) b=%b (1) -> lt=%b eq=%b gt=%b",
                 a, b, slt, seq, sgt);

        $finish;
    end
endmodule
`default_nettype wire

The testbench drives five arithmetic cases and then compares 1000 with 0001 through both comparators. The last line is the clearest evidence that signedness is a declaration, not a comment.

The actual run

Simulator output actual run · Icarus 13.0 
operation        | sum  cout zero ovf | lt eq gt
-----------------+-------------------+---------
5 + 3            | 1000   0    0    1  |  0  0  1
7 + 1 (overflow) | 1000   0    0    1  |  0  0  1
4 - 2            | 0010   1    0    0  |  0  0  1
0 - 1            | 1111   0    0    0  |  1  0  0
-8 - 1 (overflow)| 0111   1    0    1  |  0  0  1
signed compare a=1000 (-8) b=0001 (1) -> lt=1 eq=0 gt=0
tb.v:50: $finish called at 6000 (1ps)

Read the rows in order:

  • 5 + 3: the sum is 1000 (8) and cout is 0 because the unsigned result fits in four bits. The signed result 8 is outside -8 to +7, so overflow is 1.
  • 7 + 1: the same signed overflow, with the same four-bit sum.
  • 4 - 2: the sum is 0010 and cout is 1, meaning no borrow. Overflow is 0.
  • 0 - 1: the sum is 1111 (-1) and cout is 0, meaning a borrow. The signed result is in range, so overflow is 0. The unsigned comparator sees 0 < 1.
  • -8 - 1: the sum is 0111 (7) with cout 1. Negative plus negative produced positive, so overflow is 1.
  • Signed compare: the same bits 1000 and 0001 give lt = 1 when the ports are signed, because -8 < 1. The unsigned comparator in the table above gives gt = 1 for the same bits, because 8 > 1.

Common mistakes

  • Adding in the destination width. A four-bit add discards the carry. Use a wider intermediate and slice it.
  • Equating carry with overflow. They answer unsigned and signed questions respectively.
  • Forgetting the +1 in two's complement. a + ~b is a - b - 1.
  • Inverting with unary minus. -b is two's complement negation; the adder needs the bitwise complement plus a carry-in of 1.
  • Comparing signed data with unsigned ports. The comparison becomes unsigned and negative values compare as large positives.
  • Assuming subtraction needs a separate subtractor. One adder with operand inversion and carry-in is the standard datapath structure.

Revision points

  • Add in a wider context to capture the carry, then split sum and carry.
  • a - b = a + ~b + 1; the same adder can do both operations.
  • In the shared adder, cout = 1 means no borrow for subtraction.
  • Carry is unsigned range; overflow is signed range; both flags are needed.
  • Signedness is decided by the port declaration, not by the bit pattern.
