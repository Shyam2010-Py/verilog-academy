Gate Level and Data Flow Modelling

Unit overview

Selection and routing are most of a datapath

Multiplexers choose, decoders select, demultiplexers route, and encoders compress a set of requests into a code. These four blocks appear in almost every datapath, memory interface and interrupt controller. They are small enough to describe completely and important enough to get exactly right.

All four are pure combinational logic. The dataflow style is a good fit because each block is one or two equations, and the equation makes the hardware structure visible.

Multiplexer: one output, many inputs

A 4:1 multiplexer selects one of four data bits using a two-bit select. In Verilog, a variable bit-select is the compact form:

Variable indexingillustrative fragment · not a complete module
assign y = d[sel];   // sel is 2 bits, d is 4 bits

This is not "indexing an array in software". It describes a layer of 2:1 multiplexers: the select bits choose which data bit reaches the output. For small widths, synthesis maps it directly to a multiplexer tree. For large widths, the same idea becomes a bus structure, but the select must still be decoded.

Decoder: one input code, one active output

A binary-to-one-hot decoder drives exactly one output high for each input code. A 2-to-4 decoder with an enable can be written as a shift:

One-hot decoderillustrative fragment · not a complete module
assign y = en ? (4'b0001 << a) : 4'b0000;

The left operand is four bits wide, so the shift result is four bits wide. Shifting by 0, 1, 2 or 3 produces the four one-hot patterns. Shifting by 4 or more would produce zero — useful to know, because an out-of-range select is silently absorbed rather than flagged.

Demultiplexer: one input, many outputs

A demultiplexer is the reverse of a multiplexer: it routes one data bit to one of several outputs. The one-hot position is the select code, gated by the data:

1-to-4 demultiplexerillustrative fragment · not a complete module
assign y = d ? (4'b0001 << sel) : 4'b0000;

The structure is identical to the decoder, with the data bit acting as an additional enable. That is not a coincidence: a demultiplexer is a decoder whose enable is the data.

Priority encoder: many requests, one code

An encoder converts a one-hot input into a binary code. A priority encoder accepts any pattern and returns the index of the highest-priority request. If bit 3 has priority, then:

Priority encoder truth table (bit 3 highest)
reqvalidcode
0000000
0001100
0010101
0100110
1000111
1010111

The dataflow equations can be written directly from the priority order: code[1] is high when request 3 or 2 is present; code[0] is high when request 3 is present, or request 1 is present without request 2. That is the equation used in the example, and it matches the table.

All four blocks, one run

The example puts a multiplexer, a decoder, a demultiplexer and a priority encoder in one file and instantiates each one in the testbench.

example.v 
`default_nettype none
module mux4 (
    input  wire [3:0] d,
    input  wire [1:0] sel,
    output wire       y
);
    assign y = d[sel];
endmodule

module dec2to4 (
    input  wire [1:0] a,
    input  wire       en,
    output wire [3:0] y
);
    assign y = en ? (4'b0001 << a) : 4'b0000;
endmodule

module demux1to4 (
    input  wire       d,
    input  wire [1:0] sel,
    output wire [3:0] y
);
    assign y = d ? (4'b0001 << sel) : 4'b0000;
endmodule

// Priority encoder written as dataflow equations: bit 3 wins.
module priority4 (
    input  wire [3:0] req,
    output wire       valid,
    output wire [1:0] code
);
    assign valid  = |req;
    assign code[1] = req[3] | req[2];
    assign code[0] = req[3] | (req[1] & ~req[2]);
endmodule
`default_nettype wire

Line by line

  • assign y = d[sel]; selects one bit. With d = 1010, selects 00 to 11 return 0, 1, 0, 1.
  • assign y = en ? (4'b0001 << a) : 4'b0000; decodes a into one-hot form. The enable forces all outputs low when it is 0.
  • assign y = d ? (4'b0001 << sel) : 4'b0000; routes the data bit to the selected output. With d = 1, the output is the same one-hot pattern as the decoder.
  • assign valid = |req; is a reduction OR: valid is 1 if any request bit is set.
  • assign code[1] = req[3] | req[2]; and assign code[0] = req[3] | (req[1] & ~req[2]); implement the priority table. The equations are written so bit 3 dominates bit 2, and bit 2 blocks bit 1.
  • The testbench drives d = 1010, en = 1 and din = 1, then walks the select. It later walks six request patterns through the encoder.

The mux column follows the bits of 1010. The decoder and demux columns are one-hot and move the active position with the select. The encoder returns valid = 0 only for 0000, and its code follows the highest set bit: 1010 returns 3 because bit 3 wins.

Where these blocks appear

  • Multiplexers select ALU operands, register-file read ports, bus sources and pipeline results.
  • Decoders turn an address into a chip select or a register write enable.
  • Demultiplexers route a write data bit or a clock enable to one of several destinations.
  • Priority encoders resolve interrupt requests, arbitrate bus grants and find the first set bit in a word.

All four are also building blocks for larger structures: a barrel shifter is a tree of multiplexers, a register file is a decoder plus an array, and an arbiter is a priority encoder with state.

Common mistakes

  • An out-of-range select. A four-bit vector indexed by a value of 4 or more yields x. Widen the vector or guarantee the range.
  • Forgetting the shift width. 4'b0001 << a is four bits wide. Shifting by 4 gives zero, not a five-bit result.
  • Swapping encoder and decoder. A decoder expands a code to one-hot; an encoder compresses one-hot to a code. They are not inverse functions for arbitrary inputs.
  • Getting the priority order backwards. The highest-priority bit determines the code. Test overlapping patterns such as 1010, not only one-hot patterns.
  • Driving the same net from two blocks. A mux and a decoder cannot both drive y unless the net is resolved deliberately.
  • Assuming a decoder is a mux. A decoder has one input code and many outputs; a mux has many data inputs and one output.

Revision points

  • A multiplexer selects; a demultiplexer routes; a decoder expands a code to one-hot; an encoder compresses one-hot to a code.
  • Variable indexing describes a multiplexer; a left shift of a one-hot constant describes a decoder.
  • A priority encoder returns the index of the highest set bit and a valid flag.
  • Shift results keep the width of the left operand; out-of-range indices produce x.
  • Test overlapping patterns, not only one-hot inputs.
