Unit overview

Tasks for the simulator, not the chip

Verilog has two syntax families that look similar but live on opposite sides of the synthesis boundary. System tasks start with $ and run inside the simulator: printing, timing, dumping waveforms, finishing. Compiler directives start with a backtick and are processed before the design is elaborated: macros, includes, timescales, net-type rules.

Neither family describes hardware. A synthesis tool may ignore them, warn about them, or reject the file. Treating $display as part of the design is as wrong as treating a compiler flag as a gate.

The display family

Observation tasks used in testbenches
TaskBehaviour
$display(...)Prints immediately, with a newline. Sees values before non-blocking updates in the same time step.
$write(...)Prints immediately without a newline. Useful for building one line from several statements.
$strobe(...)Prints at the end of the current time step, after all non-blocking updates have been applied.
$monitor(...)Prints once at the start and again whenever any listed value changes. Only one monitor is active at a time.
$timeCurrent simulation time, scaled to the module's timescale unit.
$finishEnds the simulation and returns control to the operating system.
$stopPauses an interactive simulator. Batch runs behave differently; do not rely on it.

Format specifiers follow the task name as a string: %b binary, %o octal, %d decimal, %h hexadecimal, %s string, %t time, %m hierarchical name. A zero between % and the letter (%0d) suppresses padding.

Compiler directives you will actually use

Directives in this course
DirectiveEffect
`timescale 1ns / 1psSets the time unit and precision for delays and time formats in the modules that follow.
`define NAME valueDefines a textual macro. Use `NAME to expand it. Parenthesise macro bodies that contain operators.
`include "file.vh"Inserts another file at compile time, typically for shared macros or definitions.
`ifdef NAME ... `else ... `endifConditional compilation. Useful for simulation-only debug blocks; easy to abuse.
`default_nettype noneTurns undeclared nets into errors. Restore with `default_nettype wire at the end of the file.

The timescale applies to the modules that follow the directive in compilation order. If different files disagree, delays in one file can mean something different from delays in another. Keep one timescale per project where possible, and state it in every file that uses delays.

Display, strobe, write, finish

This testbench exercises the observation tasks and shows the difference between $display and $strobe around a non-blocking assignment.

example.v 
`timescale 1ns / 1ps
`define WIDTH 4
`default_nettype none
// Simulation tasks are for observation, not for synthesis.
module system_tasks_tb;
    reg clk;
    reg [`WIDTH-1:0] count;
    reg value;

    initial begin
        clk   = 0;
        count = 0;
        value = 0;

        $display("start at t=%0t", $time);
        #5;
        count = 4'b0011;
        $display("count=%b (%0d) at t=%0t", count, count, $time);

        value <= 1'b1;
        $display("display sees value=%b", value);
        $strobe("strobe sees value=%b", value);

        #5;
        $write("write keeps ");
        $write("the line open\n");
        $display("finish at t=%0t", $time);
        $finish;
    end

    always #2 clk = ~clk;
endmodule
`default_nettype wire

Line by line

  • `define WIDTH 4 creates a macro. `WIDTH-1 expands to 4-1, so the vector range is [3:0].
  • $display("start at t=%0t", $time); prints the start time. %0t uses the timescale to format the value.
  • At #5, count = 4'b0011; is a blocking assignment, so the next $display sees the new value.
  • value <= 1'b1; is a non-blocking assignment. The right-hand side is evaluated now, but the update is scheduled for the non-blocking region at the end of the time step.
  • $display("display sees value=%b", value); runs in the active region and therefore sees the old value, 0.
  • $strobe("strobe sees value=%b", value); runs at the end of the time step, after the update, and sees 1. This is the clearest demonstration of the scheduling difference in the whole unit.
  • $write twice builds one line: the first call prints without a newline, the second adds a newline inside its string.
  • always #2 clk = ~clk; keeps a clock running. It does not print, but it shows that an always block runs concurrently with the initial block.
  • $finish ends the run at 10 ns.
Terminal

The actual run

Simulator output actual run · Icarus 13.0 
start at t=0
count=0011 (3) at t=5000
display sees value=0
strobe sees value=1
write keeps the line open
finish at t=10000
example.v:28: $finish called at 10000 (1ps)

The pair display sees value=0 and strobe sees value=1 is not a simulator quirk. It is the scheduling model: non-blocking updates happen after the active statements in a time step. The last line shows the two $write calls joined into one line.

Dumping waves for GTKWave

For anything larger than a truth table, a waveform is easier to inspect than printed text. The standard simulation tasks write a Value Change Dump:

Testbench fragment · VCD tracenot executed in this lesson
initial begin
    $dumpfile("wave.vcd");
    $dumpvars(0, system_tasks_tb);
end

Run the simulation, then open the file with gtkwave wave.vcd. Dumping is a simulation feature; it has no hardware meaning and must not appear in synthesizable RTL.

Common mistakes

  • Putting $display in RTL. It is not hardware. Keep observation in the testbench, or guard debug code with `ifdef and remove it from release builds.
  • Using $display to check a non-blocking result. It sees the old value. Use $strobe, or check on the next time step.
  • Confusing $ and a backtick. $display is a task; `define is a directive. They are not interchangeable.
  • Forgetting $finish. A testbench with no termination can run until the event queue is empty, which may be much later than intended, or never if a clock keeps running.
  • Mismatched timescales. A #5 in a file with 1ns/1ps is 5 ns; in a file with 1ps/1ps it is 5 ps. Check the directive at the top of each file.
  • Leaving `default_nettype none active. Subsequent files that relied on implicit nets will fail. Restore the default.

Revision points

  • System tasks start with $ and are simulation-only; compiler directives start with a backtick and are processed at compile time.
  • $display runs immediately; $strobe runs after non-blocking updates at the end of the time step.
  • $write does not add a newline; $monitor prints on change and is singular.
  • `timescale sets delay units and time precision for the modules that follow it.
  • $dumpfile and $dumpvars produce a VCD for waveform viewing; they are not synthesizable.
